YouTube 客户端现状与 PO Token 问题跟踪记录
=============================================

记录日期：2026-08-05
用途：记录当前已验证的客户端表现、PO Token 故障和后续复查方向，供未来重新适配时使用。

一、当前结论
------------

1. 当前软件的普通下载与播放列表下载均固定使用 android_vr。
2. android_vr 下载公开视频时暂不需要 Cookies、PO Token、bgutil 或 Deno，已经验证可取得 4K 格式并完成批量下载。
3. mweb 和 web_creator 所需的 Cookies、PO Token、bgutil、Deno 组件及预热代码全部保留，但当前不参与下载流程。
4. PO Token 是 YouTube 正在逐步加强的访问校验机制。长期来看，稳定的“网页客户端 + PO Token Provider”仍值得继续研究，但 PO Token 本身不代表画质更高；只有 Token 生成和完整下载都稳定时，才适合重新启用。

二、测试环境
------------

- Windows 10
- yt-dlp 2026.07.04
- bgutil-ytdlp-pot-provider 1.3.1
- BgUtils 3.2.0（另做过 4.0.3 隔离验证）
- Deno 2.5.6
- Firefox Cookies

三、mweb 客户端现状
-------------------

已验证能力：

- 能提取 4K 格式并正确选择 401+251-7。
- bgutil 能为测试视频生成绑定视频 ID 的 GVS PO Token。

已验证问题：

- 测试视频：https://www.youtube.com/watch?v=CpGiJ3VRjps
- MP4 4K 格式 401 下载到约 5% 后稳定出现 HTTP 403 Forbidden。
- 重新生成 Token 和下载地址后可以短暂续传，但随后再次出现 403。
- HTTP Range 验证显示：文件前部及约 40.9MB 位置可读取，约 52MB 位置稳定返回 403；同视频 mweb 的 VP9 4K 格式 313 在该位置可以读取。

当前判断：

- 问题集中在 mweb 返回的部分 MP4 4K 下载地址或特定文件区间。
- 不是画质选择规则、文件名、普通断网或“完全没有生成 PO Token”造成的。
- 在完整视频能够稳定下载前，mweb 不适合作为软件主客户端。

四、web_creator 客户端现状
-------------------------

已验证能力：

- 需要账号 Cookies 和 GVS PO Token。
- Token 正常时可以取得 4K；早期测试中，格式 401 的多个远端区间能够正常读取，部分视频可以完整下载。

当前主要问题：

- 后续使用多个不同的新视频测试时，均出现 PO Token 生成失败。
- 更换视频和公网 IP 后问题仍存在；同一 Firefox 账号可以在浏览器中正常登录并播放这些视频。
- 已打印到底层错误：
  BGError: VM operation timed out
  code: TIMEOUT
- 错误发生在 BgUtils 3.2.0 执行 BotGuard VM 快照阶段，早于格式选择和视频下载，因此与是否选择 4K 无关。
- 单纯把快照等待时间从 3 秒提高到 10 秒仍然失败，说明不是普通的执行速度慢，而是 VM 卡住或当前挑战与模拟环境不兼容。

BgUtils 4.0.3 隔离验证：

- 4.0.3 存在破坏性 API 变化，不能只修改依赖版本。
- 完成最小适配后，异步快照仍会卡死。
- 改用同步快照后 VM 可以执行完成，但 Google GenerateIT 返回 integrityToken=null，只返回 websafeFallbackToken，无法建立正常的 GVS PO Token minter。
- 结论：当前故障不能通过简单升级 yt-dlp、延长超时或直接升级 BgUtils 4.x 修复。

当前判断：

- web_creator 的主要阻塞点是 BotGuard/PO Token Provider 链路，不是下载器画质逻辑。
- 当前不适合作为主客户端；等待 provider、BgUtils 或 YouTube 挑战兼容性发生明确变化后再复测。

五、android_vr 客户端现状
------------------------

已验证优势：

- 当前不要求 PO Token。
- 下载公开视频时不需要账号 Cookies。
- 可以取得 3840×2160 的 4K 格式，例如 401+251。
- 单视频和播放列表下载均已实际验证，整体最简单、稳定，依赖最少。
- 下载中的 DNS 解析错误可由 yt-dlp 自带重试恢复，属于网络层重试，不是客户端或画质故障。

已知限制：

- YouTube Kids/“面向儿童”视频不可用。
- 不适合必须登录后才能访问的私人、会员或部分年龄限制内容。
- YouTube 后续仍可能改变该客户端的格式供应或 PO Token 要求，需要持续观察。

当前软件配置：

- 普通下载：固定 android_vr，不读取 Cookies，不预热 PO Token 组件。
- 播放列表下载：固定 android_vr，不读取 Cookies，不预热 PO Token 组件。
- 所有 PO Token 相关组件与代码继续保留，未来适配成功后再启用。

六、未来复查顺序
----------------

1. 更新 yt-dlp 后，查看官方默认客户端和 PO Token enforcement 表是否变化。
2. 检查 bgutil-ytdlp-pot-provider 是否发布了适配新版 BgUtils 或新版 BotGuard 挑战的版本。
3. 使用本文三个场景重新验证：
   - mweb 的格式 401 是否还能在约 5% 或约 52MB 位置复现 403。
   - web_creator 能否成功获得非空 integrityToken，并完整下载新视频。
   - android_vr 是否仍能提供并完整下载 4K。
4. 不能只用“-F 能看到 4K”或“下载开始成功”作为通过标准；必须验证视频流完整下载、音频下载及 FFmpeg 合并。
5. 只有 mweb 或 web_creator 连续通过多个新视频和播放列表的完整下载，才考虑恢复“网页客户端 + PO Token”方案。
