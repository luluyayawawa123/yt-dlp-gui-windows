YouTube PO Token 问题跟踪
最近更新：2026-09-21

一、软件目前怎么使用 YouTube 客户端

普通下载：mweb + Firefox Cookies + bgutil PO Token。支持分别下载视频和音频，能选到多高的画质，仍取决于视频实际提供的格式。
播放列表/频道：同样使用 mweb + bgutil PO Token，但目前不传 Firefox Cookies。这只是沿用旧配置：新版组件先在普通模式完成测试，播放列表还没来得及改，不能因此认为不传 Cookies 更好。
普通下载中的“斗地主模式”：web_safari + Firefox Cookies，不获取 PO Token，尝试下载最高 1080P 的 HLS 流；勾选字幕时，也会尝试下载自动生成的字幕。

内置组件：官方 bgutil Provider server 与插件均为 2.0.0，bgutils-js 为 4.0.3，Deno 为 2.9.7。yt-dlp 内核可通过 bin 目录中的 BAT 文件单独更新。这次升级没有改动客户端选择、Cookies 规则或重试流程。

二、问题由来和已完成的修复

此前曾出现这样的故障：PO Token 已生成，视频格式也能列出，但真正下载媒体时返回 HTTP 403。bgutil Issue #242 记录了这一问题：
https://github.com/Brainicism/bgutil-ytdlp-pot-provider/issues/242

上游修复针对的是令牌生成时，BotGuard challenge 与同一次 YouTube 首页会话中的 ytcfg/EVENT_ID 没有正确对应的问题。BgUtils #44 和 bgutil PR #243 已修复相关逻辑；PR #243 于 2026-08-21 合并，随后发布了正式版本。上游公开测试中，成功数从旧版的 14/24 提高到修复版的 22/24，但并不保证次次成功。
https://github.com/LuanRT/BgUtils/pull/44
https://github.com/Brainicism/bgutil-ytdlp-pot-provider/pull/243
https://github.com/Brainicism/bgutil-ytdlp-pot-provider/releases/tag/2.0.0

本项目曾把 #243 的修复临时用于 1.3.1：清除旧 Token 后，原先失败的视频 zM8aeERz4BQ 成功下载并合并了 480P 视频和音频；随后在原 IP 和两个美国机房出口 IP 下也完成了下载测试。2026-09-21，项目改用官方 2.0.0 整套组件，不再保留本地补丁。

三、仍要区别对待的故障

LOGIN_REQUIRED / “Sign in to confirm you’re not a bot”：YouTube 要求登录确认不是机器人。这通常发生在生成 Token 之前，因此不是“Token 生成失败”。播放列表目前不读取 Firefox Cookies；即使 Firefox 已登录，下载请求仍是匿名的。此前，不带 Cookies 的 mweb 在 GCP 出口 IP 下可以下载，在 Linode 美国出口 IP 下稳定失败。2026-09-21 的另一次同路线测试明确收到 LOGIN_REQUIRED。这些结果表明，匿名下载的表现与出口 IP 有关，但不足以证明 IP 是唯一原因；更换 IP 可能有用，单靠更新 PO Token 组件则不能保证解决。

Token 生成失败：要看 bgutil/BotGuard 报出的具体错误，不能把所有下载失败都归到这一类。旧版 web_creator + Firefox Cookies 曾出现 `VM operation timed out`；换用官方 2.0.0 后，这条路线还没有重新测试。

媒体 HTTP 403：如果新版已经成功生成 Token，下载媒体时却仍收到 403，应保存完整日志继续排查，不能直接认定为旧版 #242 问题。软件会重新解析下载地址并尝试断点续传，但重试不保证成功。DNS 解析失败属于另一种网络错误，也不能与 403 或 Token 失败混为一谈。

四、官方版升级后的验证与待办

2026-09-21：在只解析、不下载文件的测试中，普通模式识别到了 bgutil 2.0.0，成功取得 gvs/subs Token，并选中 397+140（480P 视频和音频）。同一网络下，模拟播放列表“不带 Cookies”的请求在生成 Token 前返回 LOGIN_REQUIRED。这是单条请求测试，不代表已经完成播放列表下载测试。

随后，用户用开发版普通模式完整下载了一段 4K 视频，又测试了重新打包的绿色版，均可正常下载。这说明这两次实际测试通过，但不能推断所有视频和网络都稳定，也不能代替播放列表测试。

接下来仍要验证：普通模式在更多视频和网络下的下载、字幕与 403 自动恢复；播放列表带 Firefox Cookies 后的完整下载；绿色版改名或移动目录后的首次下载。具体安排见《软件待办事项.txt》。判断问题时，仍以当次完整日志为准。
